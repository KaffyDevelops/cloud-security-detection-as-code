# Contributing

Contributions are welcome.

Please contribute only detection content you are permitted to share.

## New Detection Checklist

- follow the directory and metadata standard
- use a unique provider-prefixed ID
- include a provider-native query
- map to MITRE ATT&CK conservatively
- include a safe test scenario
- document false positives
- provide triage and response guidance
- state limitations
- keep status at `implemented` unless test evidence exists
- run the repository validator

## Pull Requests

Explain the security problem, data source, detection logic, ATT&CK mapping, testing performed, known false positives and validation status.

Never submit credentials, private tenant data or production telemetry that has not been properly sanitised.
